# Namā Phase 2 — الوضع الصارم الاختياري

المحرك الرسمي هو `engine.js`. لم يُستبدل بـ`reference-policy.js`، ولم تُنقل الحسابات إلى محرك آخر. مسار الحول ودفعات المال وإعادة تقييم الأصول والأحداث هو المسار الحالي نفسه؛ الوضع الصارم يضيف التحقق واختيار النصاب الصحيح وفصل التعجيل. الزروع والمواشي تستخدم الدالتين العامتين الحاليتين مع خيار إضافي للحساب الذي لم يكن موجودًا في فاحص الأهلية القديم.

## قرار الانتقال

**LEGACY DEFAULT PRESERVED.** لا يوجد تغيير تلقائي إلى Strict.

التوصية: **لا تجعل Strict هو الافتراضي الآن**. الاختبارات تثبت الحساب داخل العقد الصارم، لكن المستهلكين الحاليين لم يُرحّلوا إلى مدخلاته أو حالات النتائج غير المكتملة. يلزم قرار مستقل بعد مراجعة تكامل الفريق وR01–R06. لم تُنشأ طبقة Adapter للواجهة، ولم تُعدّل Figma أو personas أو view أو الأسعار أو البحث.

## Public API

لم تُحذف أي دالة أو يُغيّر ترتيب معاملاتها. إضافة `validationMode` اختيارية؛ الاستدعاءات القديمة دونها تُبقي شكل النتائج والقيم المالية القديمة. إصلاح عزل تواريخ المدخلات يسري على الوضعين.

```js
runEngineDetailed(days); // Legacy مؤقتًا
runEngine(days);         // مصفوفة الأحداث القديمة
runEngineDetailed(days, { validationMode: 'strict' });
runEngineDetailed(days, {
  validationMode: 'strict',
  acquiredMoneyMode: 'ANNUAL_ADVANCE',
});
runEngineDetailed(days, { validationMode: 'legacy' });

calculateAssetValue(data, { validationMode: 'strict' });
calculateZakatableSnapshot(data, { validationMode: 'strict' });
evaluateCropZakat(crop, { validationMode: 'strict' });
evaluateLivestockZakat(herd, { validationMode: 'strict' });
nisabFor(prices, { validationMode: 'strict' });
```

`calculateAssetValue` دون الخيار يُعيد Number كما كان. مع Strict يُعيد `{status, value, zakat: null}`؛ القيمة هنا وعاء، وليست زكاة مستحقة. `calculateZakatableSnapshot` ليس إثبات حول: `CALCULATED` فيه يعني اكتمال حساب الوعاء فقط. نقص حقيقة لازمة يُعيد حقول القيمة الناقصة `null`، لا صفرًا.

`runEngineDetailed` الصارم يضيف `status`, `issues`, `actualDue`, `suggestedAdvance`, `paymentRecorded`, `policyApplied`، و`nisabBasis` لكل صف. `actualDue` مجموع الالتزامات المحتسبة ضمن التاريخ المقدم؛ لا يشمل تاريخًا سابقًا غير موجود ولا خصم دفعات خارجية. اقتراح التعجيل ليس دفعًا مسجلًا. `nextDue` توقع مستقبلي، لا استحقاق اليوم. إعادة بداية الدفعة بعد حدث الاستحقاق تنظّم دورة حساب الالتزام السنوي، ولا تمثل سدادًا.

`runEngine` يبقى مصفوفة أحداث. عند عدم اكتمال المدخلات الصارمة يُعيد حدث `REVIEW` يحمل الحالة والسبب، وليس مصفوفة فارغة توحي بعدم الاستحقاق. استخدم `runEngineDetailed` لقراءة الحالة الإجمالية. المعامل الثالث القديم الخاص بـresolver يبقى في Legacy؛ في Strict تُستخدم حقائق `hawlSource` المعلنة والمتحقق منها، ولا يُسمح بتجاوزها عبر callback.

لا يوجد **Breaking Change لاستدعاءات Legacy**. هناك عقد Strict جديد اختياري يجب على مستهلكيه التعامل معه صراحةً؛ ليس تغييرًا افتراضيًا لشكل Number إلى Object.

## حالات النتائج

| الحالة | الدلالة |
|---|---|
| CALCULATED | اكتمل الحساب المحدد؛ اقرأ اسم الحقل ووحدته، فالوعاء أو عدد الحيوانات ليس مبلغ سداد نقدي |
| ZERO | عدم وجوب مثبت: دون النصاب أو قبل اكتمال الحول/وقت الوجوب |
| EXEMPT | استبعاد مثبت بالغرض أو دليل يغطي الحالة |
| UNKNOWN | حقيقة لازمة مفقودة، ومنها NEEDS_HISTORY_REVIEW |
| UNRESOLVED | تحويل/تصنيف أو حالة لا يدعمها المصدر/العقد، أو نطاق إعفاء غير مثبت |
| BLOCKED_PENDING_REVIEW | حالة متأثرة مباشرة بإحدى R01–R06 |

في الحالات الثلاث الأخيرة: لا يوجد مقدار نهائي؛ تستخدم `null`، ويظهر `ruleId`, `reasonCode`, `facts`, `message`. المدخلات المستحيلة أو المتناقضة حسابيًا تُرفض بـTypeError/RangeError؛ ليست نتيجة مالية صفرية.

## عقد البيانات الصارم

### التاريخ والنقد

- التواريخ Date صالحة عند منتصف الليل UTC. النصوص، ومنها `2025-02-30`، تُرفض؛ يجب على طبقة الإدخال التحقق من النص الأصلي قبل تحويله إلى Date، لأن Date قد يطبّع يومًا مستحيلًا ويفقد النص الأصلي.
- التاريخ يومي متصل ومرتب، ومعه حقيقة الملكية منذ بدء الملاحظة. ظهور أصل لأول مرة بعد تاريخ اقتنائه دون التاريخ الفاصل يعيد NEEDS_HISTORY_REVIEW.
- مسار التدفقات يحتاج `openingBalanceKnown: true` عند البداية وقوائم deposits/withdrawals صريحة لكل يوم. هذه إقرار بمعرفة البداية قبل تدفقات أول يوم، وليست إدخال رصيد افتتاحي مجهول كصفر.
- أسعار `prices.gold` و`prices.silver` لازمة للنقد والمزيج؛ يُشتق النصاب منها. `day.nisab` القديم لا يبدل السياسة الصارمة. المعدن المنفرد غير التجاري يستخدم وزن نصابه وسعره الخالص.
- `cashBalance` إن قُدم مع التدفقات يجب أن يطابق الدفتر. جمع دفتر تدفقات مع جرد نقد يتطلب إقرار `flowsAreSeparate: true` بأنهما مالان مختلفان، وإلا UNRESOLVED منعًا للتكرار.
- الرصيد النقدي المجهول في snapshot لا يصبح صفرًا. الأرقام محدودة بنطاق المحرك، والنقد بدقة سنتين عشريتين.

### الأصول المالية

- جرد يومي كامل، وID ثابت، وDate acquired. لا إعادة استخدام ID متقاعد ولا تغيير نوع/غرض/عيار/اقتناء الدفعة تحت الهوية نفسها. مشتريات جديدة تحتاج دفعات جديدة.
- المعادن: grams وkarat أو purity وغرض صريح. السعر سعر جرام المعدن الخالص. غرض الاستخدام/الإعارة يستبعد الأصل، دون اختراع سعر. السعر المقدم للأصل يجب أن يطابق سعر المعدن المقدم لليوم إن وُجد.
- الأسهم والصناديق: type صريح `TRADING` أو `LONG_TERM`. المتاجرة تستخدم marketValue. الاستثمار يستخدم zakatableValue معلومًا يمثل الوعاء النقدي السنوي الزكوي الخاص بهذه الحصة؛ ليس NAV ولا تقديرًا لمكونات مجهولة.
- للصندوق يمكن تقديم fundZakatableBase وownershipShare بين 0 و1 بدل قيمة الحصة. إذا قُدمت قيمة الحصة أيضًا وجب تطابقها. لا يستنتج المحرك تركيب صندوق مختلط يحتوي أنظمة زكوية مختلفة من صافي أصوله.
- إعفاء السهم الاستثماري يتطلب zakatExempt وcompanyZakatPaid، ودليل companyEvidence يحوي jurisdiction `SA` وsource نصيًا وcoversHolding `true`. هذه حقائق معلنة من مدخل موثوق، وليست تحققًا آليًا من صحة مستند خارجي. سهم المضاربة لا يُعفى بمجرد دفع الشركة.
- الذمم: kind `receivable`، recovery `SOLVENT_NON_DELAYING` أو `DOUBTFUL` وقيمة معلومة. النوع الثاني مستبعد إلى التحصيل ثم يبدأ حول جديد.
- الربط الاقتصادي عند ظهور دفعة جديدة: hawlSource يحوي sourceId وtype `TRADE_PROFIT` / `TRADE_CONVERSION` / `DEBT_RECOVERY`. النقل/التحصيل يحتاج transferredValue ومطابقة انخفاض المصدر وقيمة الهدف. المسار الحالي يدعم النقل المتطابق بالقيمة؛ تغير قيمة البيع أو الرسوم يحتاج وقائع معاملات إضافية، ولا يُخمّنها.

### الزروع

classification: `GRAIN` / `STORABLE_FRUIT` / `NON_ZAKATABLE`؛ التصنيف حقيقة موثقة على المدخل، وليس قاموسًا شاملًا لكل أصناف النبات.

quantity ووحدة `L` / `SAA` / `AWSUQ`، وحالة measurementState `CLEANED_GRAIN` / `DRIED_FRUIT`، وownedAtObligation وobligationReached كقيم Boolean، وفئة irrigation.

استخدام KG مدعوم فقط مع kind `WHEAT` وgoodWheat `true`؛ لا تحويل عام للأوزان. `HALF_COST` هي الفئة الموثقة كما وردت في الدليل، وليست استنتاجًا من أي نسبة سقي مختلط. `aggregate: true` يُعاد UNRESOLVED. `dueQuantity` بوحدة quantity نفسها. `settlementValue` اختياري إذا عُرف pricePerUnit للوحدة المعلنة؛ لا سعر مخترع ولا حول للمحصول.

### المواشي

type: camels/cattle/sheep/goats، count صحيح، purpose، grazing، acquired وasOf، وcountChange.

- PRODUCTION: ALL_YEAR أو MOST_YEAR للرعي؛ FED_ALL_YEAR/FED_MOST_YEAR إعفاء. فئات الرعي الأخرى غير المحسومة UNRESOLVED.
- STABLE يقرر أن العدد المؤثر وشروط النصاب ثابتة خلال فترة الحول المقدمة؛ ليس استنتاجًا من قراءة يوم واحد.
- OFFSPRING يحتاج parentCount/offspringCount/parentsHawlStart، وthresholdReached إذا لم يبلغ الآباء النصاب. لا اختراع لتاريخ بلوغ النصاب.
- SEPARATED_MIXTURE يحتاج previousMixtureHawlEnd وindividualNisabMaintained.
- WORK يحتاج workRole واضحًا؛ حالات الاستثناء R05 محجوبة. TRADING يُوجه إلى عروض التجارة مع حقائق قيمة ونصاب وحول معلومة؛ مشاريع التسمين R03 محجوبة.
- sheepCount/goatCount يجب أن يطابقا العدد الكلي؛ عند اجتماعهما والفريضة واجبة يلزم متوسط قيمة كل نوع لحساب التناسب، وإلا UNKNOWN.
- mixture يتطلب ملاكًا موثقين وأعدادًا متطابقة وحول ملكية وحول خلطة، ومشاركة المراح والمسرح والماء والمحلب والفحل ووقت ومكان المرعى.
- lostCount يستبعد الإبل الضائعة؛ لا يعمم الحكم إلى نوع آخر ولا يخمن حول العائد بعد العثور عليه.
- alternatives فريضة عينية مع العمر والجنس، لا سعر نقدي مخترع ولا اختيار أرخص بديل. `selectedAlternative: null`. documentedSubstitutions يذكر بدل ابن اللبون الموثق، وrequirements تبين الجودة واستثناء هزال القطيع كله. التحقق من حيوان دفع فعلي أو تسوية مالية لفرق العمر ليس إجراء سداد في هذه المرحلة.
