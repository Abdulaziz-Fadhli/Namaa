# عقد العضو الثاني إلى العضو الثالث — طبقة المرجع الشرعي

## نقطة الاستدعاء

```js
import { runReferenceEngine, validateReferencePolicy } from '../engine/reference-policy.js';

const result = runReferenceEngine({
  asOfDate: '2025-04-01',
  shariaPolicy: { newMoneyMode: 'INDEPENDENT_HAWL' },
  prices: { '2025-04-01': { gold: 300, silver: 4 } },
  days: [{
    date: '2025-04-01',
    assets: [{ id: 'cash-opening', kind: 'CASH', acquired: '2025-04-01', value: 10000 }],
  }],
  liabilities: [{ id: 'owed-by-user', amount: 2000 }],
});
```

أرقام المثال أسعار اختبار، وليست أسعار السوق الحالية. العملات SAR فقط، والأسعار ريال لكل غرام خالص. الاستدعاء نقي بلا ملفات أو شبكة، قابل لاستيراد المتصفح. لا يستورد سكربت تشغيل الشخصيات الذي يستخدم node:fs. لم يُعدل أي UI ولم يُربط هذا العقد بها.

`runEngine(days, settings)` القديم يعيد الأحداث فقط؛ `runEngineDetailed` هو أساس الحساب القديم. **مدخل شاشة8 الجديد هو runReferenceEngine**؛ لا تعتبر الأعلام والإعدادات القديمة مصدقة بالمرجع. الوظائف القديمة باقية لاختبارات الثلاثاء والمقارنات القديمة، ولا تمنح إعفاءًا عامًا في العقد الجديد.

## سياسة المرجع

الحقل القابل لاختيار المستخدم فقط:

| الحقل | القيم | المعنى | المصدر |
|---|---|---|---|
| newMoneyMode | INDEPENDENT_HAWL | كل مال جديد مستقل له حوله؛ ربح التجارة يتبع أصله ولا يعامل راتبًا | ص14،19 |
| newMoneyMode | ANNUAL_ADVANCE | اقتراح تعجيل المال الأحدث مع الواجب؛ الواجب والتعجيل منفصلان | ص14،19،28 |

`ANNUAL_ADVANCE` **عرض اقتراح وليست عملية دفع**. لا يغير الحول بعد اقتراح فقط. المحرك يبقي الآجال المستقلة إلى أن يتوفر تنفيذ دفع موثق خارج هذا العقد. تعرض الشاشة هذا الحد بوضوح؛ لا تدعي أن الدفعة المعجلة واجبة أو أن تاريخ الدورة السنوية تغير. اختيار الدقة/التيسير أسماء منتج وليست ألفاظ PDF. الوظيفة تستعمل رموزًا تقنية ولا تنسبها للمرجع.

السياسة تثبت85غ ذهب خالص و595غ فضة خالصة،2.5%،عدم خصم الدين على المستخدم،استبعاد الحلي للاستعمال والإعارة،وسنة قمرية. ترفض nisabBasis وdeductDebts وjewelryTreatment وspendOrder أو أي حقل سياسة زائد. لا تعرض الذهب/الفضة فقط كنصاب بديل للنقد. أعلام الإعفاء ليست اختيارات في شاشة8.

## الأيام والأسعار

- days مصفوفة غير فارغة، وكل يوم `{date, assets}` فقط؛ أيام متصلة مرتبة ومتزايدة وتنتهي عند asOfDate. dates نصوص YYYY-MM-DD، وتحوّل إلى منتصف الليل UTC داخل العقد.
- assets مخزون كامل لكل يوم، ولو كان فارغًا. غياب الأصل عن يوم يعني إزالته. ليس ملخص معاملات بنكية خامًا. transactions/deposits/withdrawals غير مقبولة في هذا العقد؛ يعد العضو الثاني الدفعات اليومية من المصدر قبل التسليم. لا يعيد العضو الثالث توزيع المصروفات بأرقام تخمينية.
- كل أصل مستقل يحتاج id وتاريخ acquired حقيقيًا. الهوية لا تتكرر ولا يعاد استعمال هوية أزيلت. الأصل الذي يظهر بعد أول يوم يملك تاريخ ظهوره؛ التملك السابق للسجل الافتتاحي يعرض NEEDS_HISTORY_REVIEW ولا يستنتج حولًا سابقًا.
- قيمة نقد الدفعة يمكن أن تنقص مع المصروفات؛ إضافة نقد جديدة تتطلب دفعة جديدة. كمية معدن لا تزيد تحت id قديم. الأصول التجارية يعاد تقييمها يوميًا تحت نفس الهوية؛ تغير السعر ليس دخلًا مستقلًا.
- يلزم price لكل يوم، gold وsilver رقمان موجبان. تغيرهما لا يغير acquired. يحدد المورد هل الأسعار أسعار فعلية لذلك اليوم أم محمولة؛ العقد لا يتحقق من مزود الأسعار ولا يدعي أنه جلب سعرًا حيًا. ملف الشخصيات الحالي يحمل آخر سعر في7 أيام بعد2026-09-26؛ الإفصاح مطلوب من المستهلك.
- الذمم والأصول مفترضة ملكًا تامًا لمالك محدد مؤهل للزكاة؛ هذه حقائق تحقق قبل الاستدعاء، وليست سياسة قابلة للتبديل. وقف أو مال خيري أو تركة غير متاحة لا يُمرر كنقد شخصي. الحالات الخاصة لا يعالجها هذا العقد تلقائيًا.

## حقائق كل أصل

لكل صف أدناه: id غير فارغ،kind،acquired،والحقول المختصة فقط. null/undefined في الحقول المطلوبة، النصوص الرقمية،NaN،Infinity،السالب والنطاق التقني المتجاوز1e12 مرفوضة. لا zakatExempt ولا zakatable في هذا العقد.

| kind | الحقول | المعاملة |
|---|---|---|
| CASH | value، وtradeCapital:Boolean اختياري | نقد مستقل؛ tradeCapital يثبت أنه رأس مال تجارة عند رابط التحويل، وليس إعفاءًا |
| GOLD | grams،karat،purpose | الوزن النقي=grams×karat/24؛ العيار في(0,24] |
| SILVER | grams،purity،purpose | purity من1000،في(0,1000] |
| TRADE_GOODS | intent:TRADING أوPERSONAL_USE،value عند التجارة؛ quantity اختياري | التجارة بكامل قيمة اليوم؛ المقتنيات مستبعدة |
| STOCK | intent:TRADING أوINVESTMENT؛ value للمضاربة أوzakatableValue للاستثمار | قيمة زكوية معلنة لا اختراع موجودات الشركة |
| FUND أوDEBT_INSTRUMENT | intent كما الأسهم والقيم المختصة | المضاربة كاملة؛ الاستثمار بموجوداته الزكوية المعلنة |
| PROPERTY | intent:USE أوRENTAL أوTRADING؛ value للتجارة | أصل الاستعمال أوالتأجير مستبعد؛ الإيجار CASH مستقل |
| RECEIVABLE | value؛ recovery:SOLVENT_NON_DELAYING أوDOUBTFUL | الجيد كالمال في اليد؛ المشكوك مستبعد حتى القبض وحول بعده |

أغراض المعادن المقبولة: PERSONAL_USE وLENDING مستبعدان؛ SALE وTRADING وSAVED_FOR_SALE وRENTAL وINVESTMENT مؤهلة. الأصل غير المعروف أو النية الغائبة/المتناقضة تُرفض. لا يُفرض purpose من شكل المعدن. المعدن المنفرد له حد85 أو595، والنقد/التجارة أو الأثمان المضمومة تتبع الحد النقدي الأدنى.

أسهم الاستثمار فقط يمكن أن تحمل:

```js
{ companyZakatPaid: true,
  companyEvidence: { jurisdiction: 'SA', source: 'معرف أو رابط إفصاح شركة موثق' } }
```

هذا **خبر من مصدر شركة/مصرف تحقق منه العضو الثاني**، وليس مربع إعفاء بيد المستخدم. العقد يتحقق من وجود البيانات واتساقها ولا يتحقق خارجيًا من صدق الرابط أو صحة الإفصاح. المضاربة لا تستبعد بهذه الحجة، ولا تعمم على الصندوق أو أداة الدين أو المنتج المصرفي. المرجع لا يذكر إعفاء منتج نماء بعينه. ذلك يحتاج مصدرًا منفصلًا وسياسة موثقة مستقبلًا؛ لا تمرر إعفاءًا عامًا الآن.

liabilities منفصلة من `{id,amount}` للديون **على** المستخدم؛ تتحقق ولا تُخصم. RECEIVABLE للديون **له**. لا تجمع الاتجاهين في حقل واحد.

## حفظ نسب الحول

يرفق hawlSource بالأصل الهدف **عند أول ظهوره فقط**:

```js
hawlSource: { type: 'TRADE_PROFIT', sourceId: 'existing-trade-capital' }
// الهدف CASH وربح التجارة يتبع حول الأصل السابق.

hawlSource: { type: 'TRADE_CONVERSION', sourceId: 'trade-cash-lot', transferredValue: 10000 }
// كلا الطرفين مال تجارة؛ لا حول جديد لمجرد تغيير شكله.

hawlSource: { type: 'DEBT_RECOVERY', sourceId: 'receivable-lot', transferredValue: 2000 }
// دين جيد يحفظ حوله؛ مشكوك يبدأ بعد القبض.
```

الرابط يحتاج أصلًا في **اليوم السابق**، وهدفًا جديدًا. التحويل يستلزم انخفاض قيمة المصدر بنفسTransferredValue وقيمة هدف مساوية له، ومصدر واحد إلى هدف واحد في تلك العملية. التحويل المتشعب أوفرق سعر/عملة أوبيع تجاري بنفس اليوم الذي أنشئ فيه المصدر **غير مدعوم** ويُرفض بدل فقد الحول بصمت. يقدم المورد حدثًا مفصلًا منفصلًا عند الحاجة لتوسيع العقد لاحقًا. ربح التجارة الخارجي يحتاج تحديد الوالد؛ مجرد CASH بلا رابط يعني مالًا مستقلًا في مخطط الإدخال، ولا يدعي العقد اكتشاف الربح تلقائيًا من وصف البنك.

البيع غير التجاري/شراء ذهب جديد مستقل لا يستعمل TRADE_CONVERSION. لا تُغَيّر نية/عيار/حالة دين/جهة إخراج تحت الهوية نفسها. تغيير حقيقي يحتاج حدثًا جديدًا معالجةً ومراجعةً، لا تزوير تاريخ شراء جديد لتمريره.

## التعامل مع الخطأ وتوصيات UI المستقبلية

الأخطاء صريحة TypeError/RangeError. يلتقطها المستهلك ويعرض «بيانات غير مكتملة أو غير صحيحة» بدل رقم واجب0. تحويل رسالة العرض للعربية يقع في طبقة UI اللاحقة؛ لا يوجد fallback مالي داخل المحرك. لا تعرض زر اختيار حكم ثابت بالمرجع. لا تحوّل تحذير التاريخ إلى اختيار «واجب الآن» بلا قرار مستقل؛ المرجع لا يثبت هذه المعالجة لسجل مجهول البداية.

يحتاج العضو الثالث منك فعليًا: الدفعات اليومية المصنفة،المعرفات المستقرة،النيات،تواريخ التملك،مصدر نسب الأرباح/التحويلات،تقييمات الأسهم/الصناديق،حالة الدين وقدرة مدينه،إفصاح الشركة الموثق إن وجد،الأسعار ومحدوديتها،سياسة المال الجديد،والنتيجة من هذا الاستدعاء. لا تكلفه استنباط حكم أو قيمة مجهولة من UI.

الحالة: **آمن لربط شاشة8 لعرض هذه السياسة وخيار المال الجديد مع التحذيرات**. تنفيذ سداد/تعجيل حقيقي وإعادة توقيت بعد الدفع،وتكامل البنك والنسب غير المدعومة ليست جاهزة في هذه الطبقة،ولا يجوز عرضها كوظائف مكتملة.
