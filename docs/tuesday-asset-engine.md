# مدخلات محرك الأصول — مهام الثلاثاء

`runEngineDetailed(days, settings)` يحافظ على مدخلات النقد القديمة: `date` من نوع `Date`، و`deposits` و`withdrawals`، و`nisab`. عند استخدام الأصول، أضف `assets` كقائمة كاملة للأصول الموجودة في كل يوم، ولو كانت فارغة. الأيام مرتبة تصاعديًا، والأسعار والقيم اليومية مسؤولية مصدر البيانات.

كل أصل يمثل **دفعة تملك مستقلة**، وله `id` ثابت، و`kind`، و`acquired` من نوع `Date`. تغيّر القيمة السوقية لا يغيّر تاريخ التملك أو بداية الحول. أي شراء جديد أو إضافة نقد يدوي تكون دفعة جديدة بمعرّف وتاريخ مستقلين. نقصان كمية الذهب/الفضة أو النقد اليدوي يقلل الدفعة القائمة؛ المصروفات البنكية تخصم من الدفعات النقدية البنكية فقط.

| kind | بيانات التقييم |
|---|---|
| `gold` | `grams`, `karat`, `pricePerGram`؛ يستبعد `purpose: 'PERSONAL_USE'` |
| `silver` | `grams`, `purity` من 1000، `pricePerGram` |
| `stocks` | `type: 'TRADING'` مع `marketValue`، أو `LONG_TERM` مع `zakatableValue` |
| `investmentProducts` | نفس أنواع الاستثمار وقيمه |
| `properties` | `intent: 'TRADING'` مع `marketValue`؛ `USE` و`RENTAL` يستبعدان أصل العقار |
| `cash` | نقد يدوي: `value` |

`zakatExempt: true` يستبعد الأصل. القيمة الزكوية المجهولة للاستثمار طويل الأجل تُنتج `IncompleteAssetDataError` برسالة عربية، ولا تُعتبر صفرًا أو إعفاء. قيمة صفر معلنة صراحة تُقبل. دخل الإيجار يدخل عبر إيداع نقدي مسجل، ولا يُضاف مرة ثانية من `rentalIncome`.

```js
const days = [
  {
    date: new Date('2025-04-01T00:00:00Z'),
    deposits: [20000],
    withdrawals: [],
    nisab: 2380,
    assets: [{
      id: 'gold-purchase-1',
      kind: 'gold',
      acquired: new Date('2025-04-01T00:00:00Z'),
      grams: 100,
      karat: 24,
      pricePerGram: 300,
    }],
  },
  // ثم بقية الأيام، بنفس المعرّف وتاريخ التملك وبسعر كل يوم.
];
```

مخرجات النقد القديمة محفوظة. مع الأصول تُضاف `cashBalance` و`otherAssets` إلى السلسلة؛ و`assetLots` إلى النتيجة؛ و`cashBase` و`otherAssetsBase` و`assets` إلى حدث الوجوب لتبيين الدفعات وقيمها التي دخلت في الحساب. `lots` تبقى دفعات النقد البنكي. `total` يمثل الوعاء المشترك. `nextDue` يشمل جميع الدفعات، ويستخدم آخر قيمة متاحة كتوقع إذا بقي المال والأسعار كما هي.

الانقطاع تحت النصاب يعيد بداية الحول للنقد والأصول معًا. `INDEPENDENT_HAWL` يزكي الدفعات التي اكتمل حولها فقط؛ `ANNUAL_ADVANCE` يشمل المال الأحدث تعجيلًا ويعيد بداية الحول للدفعات المشمولة. حساب أصل موجود قبل بداية السجل يبدأ متابعته من أول يوم متاح، مع حفظ تاريخ تملكه الأصلي؛ لا نفترض تاريخ بلوغ نصاب غير مسجل.

المحاصيل والمواشي تظل في `evaluateCropZakat()` و`evaluateLivestockZakat()` وفق الأهلية والأنصبة المدعومة. لا تدخل في الوعاء النقدي 2.5%، ولا أضيفت نسب ري أو قواعد رعي.

## بيانات الشخصيات والإدخال اليدوي

`scripts/run-personas.js` يقرأ مخطط البيانات الموجود في المستودع ويحوّله إلى هذه المدخلات. استخدم `type` في `holdings` و`manual`، وليس `kind`، والتواريخ نصوص `YYYY-MM-DD`:

```json
{
  "manual": [
    { "id": "cash-1", "type": "cash", "acquired": "2025-04-01", "value": 2000 },
    { "id": "land-1", "type": "property", "acquired": "2025-04-01", "intent": "trading", "marketValue": 18000 }
  ]
}
```

الأنواع المدعومة في محول الشخصيات: `cash`, `gold`, `silver`, `stocks`, `fund` أو `investmentProducts`, و`property`. `intent` للاستثمار: `trading` أو `long_term`. قيم المعادن تؤخذ من ملف الأسعار. الأسهم والعقار يمكن أن يحملا `values` حسب اليوم؛ وعند وجود هذه السلسلة فإن أي يوم ناقص يُرفض. للصناديق/الأسهم طويلة الأجل استخدم `zakatableValue` أو `zakatableValues` حسب اليوم. يقرأ المحول `quantity` الاختيارية للأصول الاستثمارية؛ يجب تخصيص معرّف جديد لأي شراء إضافي. القيم الثابتة المصرح بها تُستخدم كما هي عند عدم وجود سلسلة يومية.

تاريخ التملك مطلوب للإدخال اليدوي، ويمكن أن يكون `acquired` أو `date`. محفظة خالد الافتتاحية لا تسجل تاريخ شراء؛ يستخدم التقرير أول يوم في البيانات كبداية المتابعة ويذكر هذا القيد صراحة. `disposed` الاختيارية تزيل الأصل من ذلك اليوم؛ تسجل حصيلة البيع كإيداع نقدي مستقل. لا يُضاف الأصل نفسه إلى `holdings` و`manual` معًا؛ المعرّفات في كل قائمة تميز دفعاتها.

التحويلات الداخلية بين حسابات العميل ذات حالة الإعفاء نفسها لا تنشئ دفعات نقدية. التحويل بين معفى وغير معفى يُرفض برسالة واضحة إلى أن تتوفر معالجة موثقة لتاريخ الدفعة. حسابات نماء المعفاة تظهر كرصيد مستبعد في التقرير. لم تُغير ملفات الشخصيات أو الأسعار أو سكربت توليدها، ولم يبدأ ربط واجهات الأربعاء.

## التحقق

- `npm test`، أو في بيئة Codex المقيدة: `npm test -- --configLoader runner`.
- `npm run lint`.
- `npm run build`، أو `npm run build -- --configLoader runner` في البيئة المقيدة.
- `npm run personas -- --output report.json`.

الفرق في يوم الوجوب يقارن الحاسبة التقليدية لكامل الوعاء مع زكاة الدفعات المستحقة في ذلك الحدث. مقارنة رمضان تستخدم كامل الوعاء في أول رمضان مقابل مجموع استحقاقات نماء حتى ذلك اليوم. اختلاف الفترتين والمنهجيتين موضح في التقرير؛ لا يقدم الفرق كوفر مضمون.
